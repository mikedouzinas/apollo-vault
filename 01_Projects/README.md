# Projects

Time-bound initiatives with clear completion criteria.

## What Goes Here

- Active projects with deadlines or specific outcomes
- Each project gets its own folder

## Structure

A project folder is only as complicated as the project needs. A conference talk might be one file. Something bigger tends to grow into this shape:

```
Project Name/
├── README.md      — What this is, what "done" looks like, current status.
├── Research/       — What you're reading or gathering before you commit to an approach.
├── Drafts/         — Work in progress. Old drafts stay, they're not deleted as you revise.
└── Output/         — The finished thing, or the current best version of it.
```

Not every project needs all four. A trip needs logistics and a packing list, not "Research/". Build the subfolders a project actually earns, not the ones on this list.

## When a Project Is Done

Move it to `04_Archive/` with a brief summary of what was accomplished. What you learned is still true after the project ends — archiving keeps it, deleting doesn't.
